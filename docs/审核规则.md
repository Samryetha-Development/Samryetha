# Samryetha 社区内容封禁规范

**文件编号**：SR-MOD-002
**版本**：2.2
**生效日期**：待定
**适用范围**：Samryetha 论坛全部公开内容及用户公开资料
**制定主体**：Samryetha 开发组（Samryetha-Development）

---

## 第一章 总则

**第一条（宗旨）**
为维护 Samryetha 论坛的讨论秩序，保护社区成员的人身安全与合法权益，明确内容处置的依据与边界，特制定本规范。

**第二条（适用原则）**
本规范仅为封禁事由之列举。凡未列入本规范第二章之内容，均不予封禁。

**第三条（封禁范围之限定）**
本规范所称封禁，系指内容不予公开发布之处置。封禁为对表达之直接限制，确立本规范所列举之事由，以性质明确、公开传播即足以造成实质损害者为限；封禁事由之数量因此保持最小。

**第四条（禁止因观点封禁）**
本论坛不因下列事由封禁任何内容：

（一）对学校、教师、管理制度之批评；
（二）负面情绪之表达；
（三）争议性话题之讨论；
（四）政治观点之表达、时事之评论、政策之批评。

封禁仅针对行为，不针对立场、观点或倾向。本规范不设基于观感之判断标准。

## 第二章 封禁事由

**第五条（事由之穷尽性）**
下列六类内容应予封禁。除下列六类外，不设其他封禁事由。

### 第一节 对政治主体之无理由辱骂

**第六条**
针对政府、政党、国家、政治人物等政治主体之无理由辱骂性表达，应予封禁。

**第七条（除外情形）**
下列情形不构成本条所称辱骂，不予封禁：

（一）对政策之批评；
（二）对政治事件之分析；
（三）对历史人物之评价；
（四）政治观点之表达及时事之讨论。

**第八条（判定标准）**
本条所针对者为辱骂性之表达，而非政治观点本身。批评与辱骂之区别在于：前者陈述理由，后者仅为谩骂。

### 第二节 于非隐藏版块发布露骨描写

**第九条**
于公开版块发布露骨之性描写（含情色创作、性行为细节描写等），应予封禁。

**第十条（除外情形）**
于隐藏版块（即不公开之版块，含成员制版块及私密讨论区）内发布前条所述内容者，不适用本条。

**第十一条（判定标准）**
本条所约束者为发布位置，而非内容本身。同一内容，发布于隐藏版块者不受限制，发布于公开版块者依本条处理。

### 第三节 人口贩卖、血腥内容及未成年人色情

**第十二条**
下列三类严重违法内容，应予封禁：

（一）**人口贩卖**：拐卖、贩卖人口、买卖儿童、器官买卖、介绍卖淫；
（二）**血腥视频及图片**：割喉、砍头、虐杀、分尸、尸体照片、自杀直播、虐待动物；
（三）**未成年人色情**：未成年人之露骨色情描写、儿童色情内容。

**第十三条（无除外情形）**
前条所列三类内容，无论发布于任何版块（含隐藏版块），均依本条处理，不适用任何除外情形。

### 第四节 枪支与毒品贩卖

**第十四条**
枪支、弹药、管制武器之贩卖，以及毒品、管制药品之买卖、介绍与推广，应予封禁。

**第十五条（除外情形）**
下列情形不予封禁：

（一）禁毒教育相关内容；
（二）公共安全议题之讨论；
（三）时事新闻之报道；
（四）学术性、科普性内容。

**第十六条（判定标准）**
本条所针对者为交易行为，其语境包含"出售""贩卖""有货""私聊"等交易性表述，而非话题本身。

### 第五节 针对性人身攻击

**第十七条**
针对特定个人之攻击性内容，应予封禁，包括但不限于：

（一）对特定同学或教师之侮辱、贬损、辱骂；
（二）人身威胁；
（三）涉及家庭成员之攻击；
（四）组织或煽动校园霸凌。

**第十八条（除外情形）**
下列情形不予封禁：

（一）观点之争辩；
（二）陈述理由之批评；
（三）对公众人物职务行为之评价；
（四）对教学方式之意见表达。

**第十九条（判定标准）**
本条所针对者为针对个人之攻击。批评某一观点、某一做法或某一规定，与攻击个人，性质不同。

### 第六节 无意义之重复内容

**第二十条**
刷屏性质之内容应予封禁，包括但不限于：

（一）同一语句反复发布；
（二）单一字符或单一词汇堆叠；
（三）整条内容由大量重复字符构成。

**第二十一条（除外情形）**
下列情形不予封禁：

（一）合理长度内表达情绪之重复字符；
（二）正常之强调表达；
（三）代码或技术内容中之重复符号。

**第二十二条（判定标准）**
本条所针对者为整条内容均由重复构成之情形。语句中含有若干重复字符者，属正常表达。

## 第三章 执行程序

### 第一节 处置流程

**第二十三条**
内容之处置依下列程序为之。**审核于发布之时完成，不设确认期间**：

```
内容发布 ──▶ 规则检查（确定性）
                │
                ├─ 确定性命中第二章事由 ──▶ 直接封禁（不经语义判断）
                │                          └─ 留存记录，管理员得随时复审、推翻
                │
                ├─ 全无命中 ──▶ 直接公开
                │
                └─ 命中而未达封禁程度 ──▶ 语义判断（语言模型）
                                              ├─ 认为可以通过 ──▶ 直接公开
                                              ├─ 认为可疑 ──────▶ 暂不公开，待人工复核
                                              └─ 认为应予封禁 ──▶ 直接封禁
                                                                  └─ 留存记录，管理员得随时复审、推翻
```

（一）**规则检查**：以确定性方式识别本规范第二章所列内容，含关键词匹配、字符重复率及与本人近期内容之比对；
（二）**直接封禁**：规则检查确定性命中者，内容不予公开。此为确定性判断，非属语义推测，故不待人工确认即生效力；其处置应予留存，管理员得随时复审并推翻之；
（三）**直接公开**：规则检查全无命中者，内容即时公开；
（四）**语义判断**：规则检查有所命中而未达封禁程度者，由语言模型结合上下文判定，避免语义误判。语义判断之结论直接生效力，不另设确认期间；
（五）**人工复审**：依前四项处置之内容，其属不予公开者，均进入复审队列，由管理员随时复核。经复核认为处置有误者，应立即恢复内容。人工之维持或推翻，不因机器已作处置而受限制。

### 第二节 处理结果

**第二十四条**
内容处置结果分为下列三种：

| 结果 | 发布者可见状态 | 可见范围 |
|---|---|---|
| 通过 | 内容即时公开 | 全体成员 |
| 审核中 | 显示为审核中 | 发布者本人及版主 |
| 已封禁 | 内容不予公开 | 仅管理员 |

前项「审核中」之内容，系指语义判断认为可疑、尚待人工复核者；其处置依第二十三条第四款及第五款为之。

**第二十五条（告知义务）**
内容即使不予通过，系统亦应向发布者返回处理结果并发送站内通知说明事由。不得出现发布操作无任何反馈之情形。

**第二十六条（机器处置之效力与界限）**
规则检查之确定性命中，及语义判断之结论，均直接生效力，不待人工确认。
但**封禁之最终决定权仍在人工**：凡经机器处置为不予公开者，均应留存完整记录并进入复审队列，管理员得随时维持或推翻之。机器处置之可推翻性，即为纠错环节之制度保障。
所有处置均应留存记录，包括处置方式、所依据之条款、命中规则、机器理由与判定时间；经人工处置者，并应记录处置人及处置时间。

**第二十六条之一（留存与查阅之限制）**
经处置为不予公开之内容，一律留存，不予删除。
前项留存内容及其摘要，仅管理员得查阅；发布者本人及版主均不得查阅。
前项留存内容之维持或推翻，由管理员为之。

### 第三节 处理时限

**第二十七条**
经机器处置为不予公开之内容，一律进入复审队列，由管理员随时复核。审核于发布之时完成，内容不因等待人工而滞留。
公测期间人力有限，人工复核一般于二十四小时内处理完毕。逾四十八小时未复核者，发布者可于反馈区提出。

## 第四章 不予封禁之内容

**第二十八条**
下列内容明确不予封禁：

（一）对学校、教师、管理制度之批评；
（二）负面情绪之表达；
（三）争议性话题之讨论；
（四）政治观点、时事评论及对政策之批评；
（五）不含人身攻击之观点冲突；
（六）游戏、影视、动漫、恋爱、考试焦虑等正常话题之讨论；
（七）英文、代码及数学公式之使用；
（八）一切不违反本规范第二章规定之表达。

**第二十九条**
社区成员不得因顾虑审核而不当限制其表达。如遇此类情形，应向开发组反馈，以便检讨本规范之适当性。

## 第五章 公开资料之适用

**第三十条**
昵称、简介等公开资料适用本规范第六条及第十七条之规定。

**第三十一条**
公开资料经标记为待审时，该用户原有资料继续对外显示，不因资料修改而影响账号之正常状态。
经审核不予通过者，其修改后之资料不予公开，亦不予删除，依第二十六条之一留存。
前两项所称原有资料，指该用户上一次经审核通过之昵称与简介；审核通过后，修改后之资料即行生效。

## 第六章 申诉

**第三十二条（申诉方式）**
对封禁处置有异议者，得依下列方式提出申诉：

（一）于反馈区发布主题，标题注明"封禁申诉"；
（二）附具内容截图或链接；
（三）说明不应封禁之理由，并指明所依据之本规范条款。

**第三十三条（复核程序）**
申诉由未参与原处置之管理员复核。复核时应调取完整记录，包括所命中规则、机器判定理由、处置方式及原处置人。

**第三十四条（复核结果）**
经复核确认误封者，应立即恢复内容，并对相关规则或阈值作出调整。
前项恢复，包括推翻机器所为之封禁处置。

**第三十五条（误封之防免）**
本规范以宁可漏放、不可误封为原则。机器之封禁处置得由人工随时推翻，即为纠错环节之制度保障。
规则检查之确定性命中须以文义明确者为限；语义判断之结论须可复核。如实际执行与本条不符，应向开发组反馈。

## 第七章 规范之修订

**第三十六条**
本规范得依公测反馈予以修订，修订内容于公告板公示。

**第三十七条**
修订应以减少误封为优先方向。某项规则导致正常表达频繁受拦者，应收紧其触发条件或予以移除。

**第三十八条**
本规范第二章所列封禁事由仅得减少，不得增加；但出现新的、性质明确之损害类型者，不在此限。

## 附录乙：技术实现说明

本附录供具备技术背景之成员查阅，并供社区监督本规范之执行是否与实现一致。

| 环节 | 实现方式 |
|---|---|
| 规则检查 | 确定性关键词匹配及结构化检测（字符重复率、与本人近期内容之比对） |
| 位置识别 | 露骨描写规则仅于公开版块生效，隐藏版块（members / private）自动豁免 |
| 语义判断 | 语言模型（Kimi K2.8 Preview），输出结构化判定：`risk` 值 0–100、类别、中文理由 |
| 判定合并 | 规则判定与语义判定取其严者；语义判定不得将规则命中降级 |
| 标记待审 | 判定为不予通过者，内容状态记为待审（`pending`），对普通成员不可见；机器不直接成立封禁 |
| 资料之待审 | 昵称、简介之修改另存待审副本，原有资料继续对外显示；审核通过后修改内容方始生效 |
| 处置分流 | 规则检查确定性命中者直接封禁（不调用模型）；全无命中者直接公开；有所命中而未达封禁程度者交由语义判断 |
| 人工复审 | 经机器处置为不予公开者均进入队列，由管理员随时维持或推翻；不设确认期间 |
| 先行处置 | 复审结论即时生效但非终局；人工可维持或推翻，推翻与否均予记录 |
| 降级策略 | 语义模型不可用时自动降级为纯规则检查；不因模型故障而阻碍内容发布。复审失败时从慎处理，并提示人工确认 |
| 查阅限制 | 不予公开之留存内容，仅管理员得查阅；发布者本人及版主均不得查阅 |
| 记录留存 | 每次判定及处置均予留痕：命中规则、机器理由、复审结论、处置方式、处置人、时间 |

**下列三项原则接受社区监督**：

（一）机器之封禁处置均非终局。规则命中之确定性判断与语义判断之结论虽直接生效力，但一律留存记录并进入复审队列，人工得随时推翻。
（二）模型故障不影响内容发布。语义服务不可用时自动降级，社区运转不受影响。
（三）封禁事由限于六类。本规范所列事由之外的内容不予封禁，不因机器判定结果而改变。
